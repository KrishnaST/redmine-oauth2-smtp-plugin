Microsoft 365 SMTP for Redmine

Browser sign-in + S256 PKCE · Delegated SMTP.Send · Native outgoing notifications

Version 2 replaces application-only authentication. It does not use SMTP.SendAsApp. Existing installations must configure a Web callback and connect interactively. Installation does not enable sending.

1. Microsoft Entra setup

  1. Use a single-tenant application registration. Record the tenant GUID and application/client GUID.
  2. Add delegated https://outlook.office.com/SMTP.Send. The plugin also requests offline_access. Grant consent as required by tenant policy.
  3. Add a Web redirect URI (not SPA):
    https://redmine.example.com/admin/microsoft365_smtp/callback
    Use your actual public HTTPS hostname and any Redmine URL prefix. The saved URI must match exactly.
  4. Create a confidential-client secret. Enter its Value, not Secret ID, in the plugin's masked Client secret field and save. It is encrypted and never displayed again. A private server file remains an optional fallback. Record expiry and plan rotation.
  5. Ensure OAuth SMTP AUTH is allowed for the sending mailbox and tenant sign-in/MFA policies permit access.

No application SMTP.SendAsApp, Exchange app service-principal grant, Graph User.Read/Mail.Send, implicit flow, or public-client/device-code activation is required by this implementation.

Do not disable tenant protections merely to force SMTP access. A tenant administrator may still need to approve delegated consent or mailbox protocol access.

2. Install or upgrade while disabled

Verified target family: Redmine 7.0.2, Rails 8.1.4, Ruby 4.0.6, Mail 2.9.1 and net-smtp 0.5.2 on Linux. No new production gem or database migration.

  1. Build using tools/package.ps1. Extract dist/redmine_microsoft365_smtp-2.0.3.zip into the Redmine plugins folder.
  2. For an upgrade, disable the installed plugin and replace its entire folder during an approved change window. Do not merge individual old files.
  3. Provision private secret/state paths outside web-served locations, owned by the Redmine service account. Examples below use the account redmine:
sudo install -d -m 700 -o redmine -g redmine /etc/redmine/secrets
sudo install -d -m 700 -o redmine -g redmine /var/lib/redmine-m365

Recommended UI setup: enter the secret Value on the same settings page as the tenant/client IDs. Blank preserves the saved secret; Remove page-managed secret clears it and restores server fallback. If using a fallback file instead, provision /etc/redmine/secrets/m365-client-secret securely as a non-symlink regular file, mode 0600, root/service owned. Never place secrets in shell history.

Service environment variableValue / purpose
REDMINE_M365_CLIENT_SECRET_FILEOptional fallback only when no encrypted page secret exists. Invalid file never falls back to environment.
REDMINE_M365_CLIENT_SECRETAlternative secret environment value, only when no secret-file path is set.
REDMINE_M365_STATE_DIRECTORY/var/lib/redmine-m365; required durable 0700 service-owned directory, no symlink paths.

Apply the environment to all web and background-worker processes. They must share the same stable Redmine secret_key_base and local state directory. Grants are AES-256-GCM encrypted with a purpose-separated key derived from that secret.

Before browser sign-in, suppress callback query strings in gateway, reverse-proxy, access, APM and analytics logs. Do not log HTTP/SMTP bodies. Rails filters authorization code, state and credentials, but cannot control external logs.

Restart the affected Redmine services. Keep the prior transport configuration intact for rollback. Examples use generic paths; substitute actual deployment paths and account.

3. Configure and connect the mailbox

Open Administration → Plugins → Microsoft 365 SMTP OAuth2 → Configure.

Automatic values (not inputs)Callback is displayed read-only, derived from Redmine's configured HTTPS public URL and application prefix. EHLO uses its hostname; timeouts are fixed at 15/30 seconds. Register the displayed callback exactly in Entra.
  1. Save settings while disabled.
  2. Click the blue Connect Microsoft button directly on the settings page. It opens Microsoft sign-in without an intermediate page. The connection-status link provides status and disconnect controls.
  3. Sign in to Microsoft as the intended sending mailbox. Complete consent/MFA. Return in the same logged-in Redmine administrator browser session.
  4. The plugin validates one-use state and S256 PKCE, exchanges the code, and checks SMTP AUTH for the configured mailbox. No message is sent.
  5. Enable only when ready. Open the test page and explicitly send one message to the current administrator's own primary email. Confirm receipt before ordinary notifications.

Connect does not log users into Redmine, assert identity through Graph/OIDC, or automatically enable delivery. SMTP authentication is not an inbox-delivery guarantee. Only the newest attempt is valid; it expires after ten minutes.

4. Operation, security and rollback

  • Refresh tokens renew access automatically. Rotated tokens are encrypted and durably saved before SMTP submission under a cross-process file lock.
  • Tenant, client, mailbox or callback changes require reconnecting. Consent revocation, sign-in policy or secret expiry can also require administrator action.
  • Disconnect clears local grants/pending attempts and disables the plugin. Revoke the application grant in Microsoft separately when retiring access.
  • Uncheck Enable to restore the original configured transport for newly delivered messages. Removing the plugin requires restarting web/workers; no migration.
  • Protect the encryption secret and state together. Losing or rotating Redmine's secret_key_base requires reconnecting. Do not delete a lock file while workers are active.
  • One installation-wide grant and one pending attempt. Supported storage topology is one host/shared local filesystem, not independent copies across multiple hosts.

Required outbound network: HTTPS 443 to login.microsoftonline.com; SMTP 587 to smtp.office365.com; DNS, correct time and trusted CA certificates. SMTP uses mandatory STARTTLS, peer verification, TLS 1.2+ and XOAUTH2. No fallback to password/application authentication and no unsafe resend after DATA.
